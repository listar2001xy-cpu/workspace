# 需求基线 v0.1

> 状态：初稿。标 `[待确认]` 的数值是我给的默认值，你确认后去掉标记。
> 范围：单通道 MVP（2026-08-17 起，目标 3 个月）。8 通道 R+C 切换为后续项目。

## 1. 功能需求 (FR)

### FR-1 电阻测量
- 范围：1Ω ~ 100kΩ（`[待确认]` 是否首期就需要两端 mΩ/MΩ）
- 精度：±0.5%（中期目标 ±0.1%）
- 方法：恒流法 `Rx = V / I`（ADS1220 IDAC）
- **验收**：100Ω / 1kΩ / 10kΩ 标准电阻各测 10 次，误差 ≤0.5%

### FR-2 采样率三档
- 100 / 500 / 1000 Hz，软件可切换
- 切换完成时间 < 100ms
- 实现：ADC 定速 2000SPS + 固件抽取 ÷2/÷4/÷20
- **验收**：实际采样率偏差 <1%

### FR-3 无线传输
- BLE（Nordic UART Service）→ 微信小程序
- 端到端延迟 < 50ms
- 丢包率 < 0.1%（序号 + CRC8 检测）
- **验收**：连续 1 小时统计丢包与延迟

### FR-4 实时可视化
- 小程序 canvas 实时绘制单条波形
- 三档采样率可切换
- **验收**：波形滚动流畅，切档生效

### FR-5 数据存储与回放
- 数据批量上传微信云开发（1 秒一批）
- 支持历史回放
- **验收**：重开小程序可查询历史数据

## 2. 非功能需求 (NFR)

### NFR-1 可靠性
- 连续运行 ≥24h 无死机（看门狗 + 状态机恢复）
- BLE 断线自动重连，重连期间数据本地缓冲不丢

### NFR-2 可维护性
- 分层架构 hal/core/app，ADC 抽象接口
- 换 ADC 芯片（ADS1220→ADS1256→AD7124-8）只改实现文件，上层零改动

### NFR-3 可追溯
- 需求 → 设计 → 实现 → 测试 可追溯（docs/traceability.md）
